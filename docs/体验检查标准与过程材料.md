# 体验检查标准与过程材料

> 项目代号：mock-interview-platform · 交付编号 D4 · 版本 V4.1 · 2026-09

## 一、自拟体验检查标准（≥5 条，作抽查依据）

1. **零门槛主流程**：新注册用户无需阅读源码，从配置页到报告页可独立完成一场完整面试闭环（配置 → 调试 → 开场 → 语音作答 → 结束 → 报告）。
2. **语音主路径可用**：Chrome / Edge（Windows）下「开始作答」开麦转写 → 「结束作答」提交（或停顿约 3.5s 自动提交）可完整走通；面试官开场白 / 题目 / 点评均有语音播报与逐字高亮。
3. **开场与推进**：每次新面试先由面试官语音开场并引导自我介绍，第 1 题固定为自我介绍；逐题为“作答 → 点评 → 追问 → 下一题”，不存在固定念题。
4. **收尾一致性**：通过关键词结束、手动结束、限题答完、过程分达 80 分提前结束四种方式，均可得到五维评分 + 知识总结 + 逐题点评。
5. **评分规范可验证**：未作答（空白或 <20 字）题目在报告中为 0 分；每维 comment 引用「第 N 题」作答；综合分与逐题质量均值偏差不超过 10 分。
6. **配额闭环**：配额未用尽时可正常创建面试并显示剩余次数；配额用尽时创建被拦截并给出明确提示；设备调试阶段不消耗配额。
7. **报告可解释且可导出**：报告单屏展示，综合得分以环形进度环 + 等级徽章（A/B/C/D）呈现；每个评分维度均有说明，逐题可展开查看作答 / 点评 / 参考示范，弱项题（评定 ≤2/4）自动红边标记并支持「仅看弱项」过滤；右上角可导出 Markdown 完整报告，简历诊断含 0-100 评分与五维。
8. **文档可复现**：第三方按 `README.md` 可在 5 分钟内启动前后端并完成一次主流程演示。

抽查预案（对应任务书第十章）：修改媒体权限 → 调试页给出授权提示与「重新获取」，未通过也可进入但语音受限有明示；更换简历/JD → 出题与摘要随之变化；请求中断（关闭 VS / 重启后端）→ 前端给出连接提示且已保存的数据可继续。

### 2.2 问题修复记录（节选）

- `sample_answer` 列缺失导致评分失败 → schema 增 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`，启动时幂等迁移
- 评分模型偶发不返回示范答案 → `ensureSampleAnswers` 逐题兜底补生成，REST 与 WS 双路径调用
- WebSocket 端口代理不通 → vite `/ws`（ws:true）代理到 3000，前端用 `location.host` 建连
- PGlite 无 pgcrypto 扩展 → 建库过滤该扩展语句；`gen_random_uuid()` 可用
- **AI 语音被识别成面试者语音** → `speak` 取消/中断的 `onerror` 不再重启识别；`aiSpeakingRef` 贯穿 startRecognition/onresult/onend，播报期丢弃识别结果
- 开场与首题脱节（自我介绍内容被当作技术题作答）→ 首题固定为自我介绍（Q0 成题并参与评分）
- JSON 未转义 / 评分飘高 → 逐题 quality 0-4 + 3 条档位约束 + 综合分后端校验修正
- 报告整页超长难用 → 固定单屏布局，左右栏等高内滚，得分总览紧凑化
- 简历报告写成泛泛面试点评 → 改为基于本场作答的简历诊断（0-100 + 五维），存入 `raw_content` JSON
