# 体验检查标准与过程材料

## 一、自拟体验检查标准（≥5 条，作抽查依据）

1. **零门槛主流程**：新注册用户无需阅读源码，从配置页到报告页可独立完成一场完整面试闭环（配置 → 入房 → 结束 → 报告）。
2. **语音降级可用**：当媒体权限被拒或浏览器不支持语音识别时，系统自动切换文字对话模式，且一场面试仍可完整评分出报告。
3. **开场与推进**：每次新面试开始，先出现开场白（问候 + 自我介绍引导）再接第 1 题；逐题之间为“作答 → 点评 → 追问 → 下一题”，不存在固定念题。
4. **收尾一致性**：通过关键词结束、手动结束、限题答完三种方式结束面试，均可得到五维评分 + 知识总结 + 逐题点评。
5. **配额闭环**：配额未用尽时可正常创建面试并显示剩余次数；配额用尽时创建被拦截并给出明确提示。
6. **报告可解释**：报告展示的每个评分维度均有说明，逐题可展开查看作答 / 点评 / 参考示范。
7. **文档可复现**：第三方按 `README.md` 可在 5 分钟内启动前后端并完成一次主流程演示。

抽查预案（对应任务书第十章）：修改媒体权限 → 应自动降级文字模式；更换简历/JD → 出题与摘要随之变化；请求中断（关闭 VS / 重启后端）→ 前端给出连接提示且已保存的数据可继续。

### 2.2 问题修复记录（节选）

- `sample_answer` 列缺失导致评分失败 → schema 增 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`，启动时幂等迁移
- 评分模型偶发不返回示范答案 → `ensureSampleAnswers` 逐题兜底补生成，REST 与 WS 双路径调用
- WebSocket 端口代理不通 → vite `/ws`（ws:true）代理到 3000，前端用 `location.host` 建连
- PGlite 无 pgcrypto 扩展 → 建库过滤该扩展语句；`gen_random_uuid()` 可用
- 媒体权限被拒直接阻断整场面试 → 改为自动降级文字对话模式（新增 WS `answer` 消息）
- 开局无开场阶段 → WS 首帧新增 `opening` 事件
- 默认岗位不符合任务书（数据分析）→ 新增 `data` 岗位并设为默认
