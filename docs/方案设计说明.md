# 方案设计说明（任务书附件 Q1–Q8）

> 项目代号：mock-interview-platform · 交付编号 D2 / D5 · 版本 V4.1 · 2026-09

本文件记录关键设计决策与理由，作为开题、中期与答辩底稿。现场说明与本文件保持一致。

## 功能亮点（答辩 / 演示速览）

- **一套引擎、五种岗位**：后端 / 前端 / 算法 / 产品 / 数据分析。切换岗位只替换人设与考察重心，出题、点评、评分主线完全一致；可再叠加目标公司、技术要求、岗位 JD、简历，答案开口就问“你是谁”，不问准备好的题。
- **一场完整面试，不是单题测验**：面试官语音开场（问候 + 训练声明 + 自我介绍引导，逐字高亮）→ 第 1 题固定自我介绍 → 逐题“作答 → 点评 → 针对性追问 → 下一题” → 四种方式收尾（关键词 / 按钮 / 答完既定量 / 过程分达 80 分提前结束）。
- **真·语音对话**：按钮式作答（点「开始作答」开麦转写，说完点「结束作答」或停顿约 3.5 秒自动提交），面试期间可随时「插话」打断；AI 说话时识别自动停用，杜绝“把 AI 语音当成你的回答”这种低级事故。
- **设备调试前置（可选）**：扬声器、麦克风波形、语音识别回显、摄像头预览四项检测，未全部通过也可直接进入——绝不因调试卡死训练。
- **评分不乱给**：未作答（空白或 <20 字）一律 0 分；每个维度评分必须引用「第 N 题」的具体作答；档位硬约束（完整 85-100 … 未作答 0-29）；综合分由逐题质量加权得出，AI 偏差超过 10 分后端强制修正。
- **报告一屏看全 + 一键导出**：单屏布局（左右栏内滚），综合得分以 SVG 环形进度环 + 等级徽章（A/B/C/D）呈现，逐题弱项自动红边标记并支持「仅看弱项」过滤；五维评分、逐题作答/点评/示范答案、知识总结、口头禅统计、简历诊断（0-100 总分 + 五维+评语）齐备；右上角「导出报告」直接下载 Markdown 全文。
- **临场感三件套（仿 InterviewIQ 设计语言）**：固定题量时顶部实时进度条（`第 N / X 题 · %`）；作答中摄像头画面亮起红色脉冲 LIVE 徽章；面试官卡片可一键「重听当前题」语音复播。
- **程序入口页（01）**：根路径登录后先见欢迎页（能力三卡 + 开始准备 / 面试记录双 CTA），点「开始准备面试」进入 `/setup` 配置；准备页顶部 STEP 1/2 分步胶囊，当前步金亮、完成步打勾。
- **简历诊断不是泛泛而谈**：基于本场面试实际作答，反向诊断简历在岗位匹配、量化、结构、亮点、面试一致性五个维度的问题，评分与改法都有出处。
- **体验统一奢华**：近黑底 + 香槟金光晕、MI 品牌导航（01 入口 → 04 总结）、流程感分页圆点，整站同一套设计语言，演示截图即宣传页。

## Q1 训练定位与考察重心

- **默认岗位**：数据分析及相关业务岗位（任务书 2.3）。考察重心：SQL 与取数、统计与概率基础、指标体系搭建、AB 实验方法、数据可视化与业务洞察表达（`packages/data` 中 `roleLine.data` 对应人设提示词）。
- **扩展岗位**：后端开发、前端开发、算法、产品经理（同一套引擎，仅人设与重点不同）。
- **取舍依据**：任务书明确默认数据分析；保留其余岗位用于演示覆盖面对比，答辩时说明扩岗仅改人设、不改变主流程。

## Q2 场次定义与结束条件

- **开始**：登录后先见程序入口页（01），点「开始准备面试」进入 `/setup` 配置；创建面试即固定生成**第 1 题「自我介绍（1 分钟）」**（`routes/interviews.ts` POST 直插 Q0），正式技术题从第 2 题起（`advanceQuestion` 出题），索引与报告逐题对齐。
- **调试前置**：进入房间先做可选「设备调试」（扬声器 / 麦克风 / 语音识别 / 摄像头），通过与否都不强制，此阶段不出题、不消耗配额。
- **开场**：WS 首帧发送开场白（问候 + 教学训练声明 + 自我介绍引导），并按**语音播报通道**开口说出，前端逐字金高亮（`rt/interview-ws.ts#serveQuestion` + `speak`）。
- **推进**：按钮式语音作答——`startAnswer` 开麦转写 → `finishAnswer` 提交（或停顿约 3.5s 自动提交）→ AI 点评（肯定 / 不足 / 1 个追问）→ 下一题；追问上限 1 轮，半双工轮转，防止会话失控。
- **结束**：四种途径——① 关键词（"结束对话 / 回答完毕 / 今天就到这 / 结束面试"）；② 手动点「结束面试」；③ 限题模式答完既定题数；④ 累计过程分达 80 分提前结束（`reachedTargetScore`，逐题质量从严换算）。
- **收束**：`handleEnding` 统一收尾：补齐题目 → 状态置 complete → 五维评分 + 知识总结 + 逐题示范答案，前端跳报告。

## Q3 材料进入方式与缺失处理

- **进入方式**：简历文本、JD、目标公司业务/技术栈、所选技术要求合并注入人设 system prompt（`packages/data#getPersona`）。
- **缺失处理**：简历未上传时摘要明示"未上传"，按通用岗位标准问答，评分不受阻断；JD 未填时按岗位 + 技术清单出题。

## Q4 追问、换题与收束原则

- 作答后 AI 先肯定正确部分、指出不足，再给 1 个针对性追问；追问后本题结束换下一题（难度递增、不重复）。
- 追问次数固定 1 轮（`interview-ws.ts` followupCount 上限），避免无目标闲聊；单次追问只针对一个具体的点，不并列多个问题。
- 检测到结束关键词即刻进入 `handleEnding`。

## Q5 语音主路径与备用路径

- **主路径**：语音是主要作答方式。前端 Web Speech API（webkitSpeechRecognition 中文识别 + speechSynthesis 本地 TTS）；后端配置 TTS Key 时改用服务端合成音频回传；开场白与题目追问均走语音播报。
- **作答交互**：按钮触发式——点「开始作答」才开麦；「结束作答」或停顿约 3.5s 自动提交；AI 说话期间识别被停用，TTS 取消类事件不会误启识别。
- **备用路径（文字兜底）**：媒体权限被拒 / 识别不可用 / 浏览器不支持时，明确提示授权并可在调试页重试；房间内点「文字作答」即输入提交，答题、点评、评分与语音完全一致，训练不中断。（对应任务书 2.2.5、第八章"权限不可用时保留文字路径"）
- **可演示环境承诺**：最新版 Chrome / Edge（Windows）可完整演示语音主路径全流程；任意现代浏览器可用文字兜底完成全流程。

## Q6 评价反馈策略

- **解决什么问题**：让受训者知道"答得如何、差在哪、怎么补"。
- **维度组织（可解释）**：技术准确性、逻辑表达、沟通流畅度、应变能力、综合评分；每题含作答实录、面试官点评、参考示范；另有知识总结、口头禅统计、简历诊断报告。
- **不乱评分（规范化）**：作答为空或少于 20 字一律按「未作答 0 分」，禁止 AI 脑补；每维 comment 必须引用「第 N 题」的具体作答；档位硬约束（完整 85-100 / 大部分 70-84 / 部分 50-69 / 含糊 30-49 / 未作答 0-29）；综合分 = 逐题质量加权均值，AI 偏差超 10 分后端强制修正（`finalizeInterScore` + WS `handleEnding` 双重校验）。
- **报告呈现**：单屏布局（左右两栏栏内滚动），综合得分环形进度环 + 等级徽章（A/B/C/D），逐题弱项红边标记与「仅看弱项」过滤；右上角「导出报告」下载 Markdown 全文；简历诊断基于本场面试实况给简历评分（0-100 + 五维），存放在 `resume_reports.raw_content`（JSON），前端解析渲染。

## Q7 次数管理与公平安排

- `users` 表 `quota_limit`（默认 5）、`quota_date`、`quota_used`；按自然日重置，创建面试时原子消费（`routes/interviews.ts` POST）；设备调试阶段不消费。
- 配置页展示「今日剩余次数」，用尽后创建返回 403 并提示"明日起自动恢复"。
- 公平性：同一配额口径对全体用户一致；无内购强制项；答辩时可现场演示配额耗尽与恢复。

## Q8 主要风险与应对

| 风险 | 应对 |
| --- | --- |
| 中国大陆语音 API 不可用 | 识别走浏览器 Web Speech API；TTS 用浏览器本地 synthesis，无 Key 时文字播报占位 |
| LLM 超时 / 失败 | `llm.ts#chat` 失败降级 mock 回复，不返回 500 |
| 识别乱码 / 空结果 | 空文本不提交并提示重说；「开始作答」按钮式触发降低误识别 |
| 媒体权限被拒 | 调试页提示授权 + 「重新获取」；未通过也可进入，功能受限但有明示 |
| AI 语音被误识别为作答 | `aiSpeakingRef` 同步铁闸：播报期停用识别，TTS 取消/中断不重启识别 |
| 评分乱给 / 虚高 | 未作答 0 分、comment 引用第 N 题、档位硬约束、综合分按逐题加权并后端校验 |
| 数据泄露 / 清理 | 密钥在 .env 不入库；数据存本地 PGlite，删除目录即清 |
| 会话失控（无限追问） | 单题追问上限 1 轮、一题一答、半双工轮转 |
